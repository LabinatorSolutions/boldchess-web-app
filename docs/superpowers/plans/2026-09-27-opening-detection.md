# Opening Detection and Explorer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Name the opening of the shown position, list the book continuations, and play a named
line or a continuation as a revertable variation.

**Architecture:**
- The lichess TSVs are vendored and converted at build time into `public/data/openings.json`
  (validated lines).
- A DOM-free `openings/book.js` indexes the lines by position key in the browser.
- `ui/opening-view.js` renders the Opening window and the header segment from `updateInfo()`.

**Tech Stack:** Vanilla ES modules (no bundler), JSDoc + `tsc --checkJs`, Bun test, Biome,
headless-Chromium smoke (`scripts/browser-smoke.js`).

**Spec:** `docs/superpowers/specs/2026-09-27-opening-detection-design.md`

## Global Constraints

- **No DOM** in `public/src/openings/book.js`; it must import under `bun test`, like `chess/`
  and `eval/`.
- **Generated file:** `public/data/openings.json` is never hand-edited. It is regenerated by
  `bun run build:openings` and drift-checked in `bun run ci`.
- **Upstream pin:** `c67912be581f0793dbaa776be5ccf111e01f88d9` (lichess-org/chess-openings,
  CC0 1.0).
- **No inline styles:** no `style=` attributes in markup and no inline scripts (CSP). Styling
  goes in `styles.css` by class.
- **Controls built in script** go through `makeButton()` (`ui/dom.js`).
- **New DOM-node properties** are declared in `types/globals.d.ts`.
- **Mode rule:** click actions only when `state.gameMode === 1`. Never infer "a game" from
  `state.play` (mode 4 sets it to null).
- **`loadBook()`** never throws and never writes to the console.
- **Copy, verbatim:** `Opening`, `Opening explorer` (spoken panel name), `Loading opening book…`,
  `Opening book unavailable`, `No opening`, `Out of book after <n>. <san>` /
  `Out of book after <n>… <san>`.
- **Commits:** a short message, no `Co-Authored-By` or session trailers (project CLAUDE.md).
  Push after each task. `master` auto-deploys.

## Spec amendment (made while planning)

The chessboard box's header bar is absolutely positioned (`.boxTop`, 24px), and the search box
sits at a fixed `top: 24px`. A separate line under it would move the board and break the fixed
geometry. So the header name is a **segment inside the existing `#positionInfo` bar**:

```html
<div id="positionInfo" class="boxTop"><span id="positionText"></span><span id="openingInfo"></span></div>
```

It is rendered as `Position: 6 of 6 - Last Move: 3. Bb5 · C60 Ruy Lopez`, with the bar's
existing ellipsis. It is still hidden on mobile with `#positionInfo`. Task 3 updates the spec's
"Board header line" section to match.

## Review Focus

1. **Promotion inside a book line** (the Lasker Trap ends `7...fxg1=N+`). The move string
   round-trips as `f2g1n`, and the line resolves by name.
2. **En passant field mismatch.** After `1.e4`, the app's FEN has `e3`, while a pasted FEN of the
   same position has `-`. `positionKey` keeps the en passant square only when an en passant
   capture is legal, so both give the same key.
3. **Clicking the name while already in a variation.** The existing `history2` snapshot is kept,
   and Revert returns to the original game, not the variation.
4. **A history starting from a custom FEN, or a FEN jump mid-game** (entries with null move).
   The walk-back still works per position, and "No opening" shows when nothing matches.
5. **Switching to a game mode with the window open.** The name and rows re-render as plain
   text, with no `onclick`.

### Task 2: Book index (`book.js`)

**Files:**
- Modify: `public/src/openings/book.js`.
- Test: `tests/openings.test.js`.

**Interfaces:**
- Consumes: `moveFromString` and the JSON shape from Task 1.
- Produces:
  - `positionKey(fen: string) -> string | null`:
    - The first four FEN fields, after a `parseFEN`/`generateFEN` round trip.
    - The en passant field becomes `-` unless `genMoves` has a pawn capture onto that square.
    - Returns null if `parseFEN` fails.
  - `buildBook(lines: Array<[string,string,string]>) -> Book`, where
    `Book = Map<string, BookNode>` and
    `BookNode = {eco: string|null, name: string|null, lineIndex: number, next: Map<string, {key: string, lineCount: number, lineIndex: number}>}`.
    - `lineIndex` is -1 when the position is unnamed.
    - On an edge, `lineIndex` is the shortest line through that edge; ties go to the lower
      index.
    - The first line in file order to end at a position names it.
  - `openingAt(book: Book, entries: Array<{fen: string, san: string|null}>, index: number) -> null | {eco, name, lineIndex, plyIndex, inBook, lastBookIndex}`:
    - `plyIndex` is the entry that carries the name.
    - `lastBookIndex` is the largest `i <= index` whose position is in the book (-1 if none).
    - `inBook` is `lastBookIndex === index`.
  - `continuations(book: Book, fen: string) -> Array<{move: string, key: string, name: string, eco: string, lineCount: number}>`:
    - The name is the child node's own name, else the name of the edge's `lineIndex` line.
    - Sorted by `lineCount` descending, then `move` ascending. SAN is the view's job.
  - `isBookPosition(book: Book, fen: string) -> boolean`.
  - `loadBook(url = "data/openings.json") -> Promise<Book|null>`: memoized, with `try/catch`
    around fetch, parse and build, and it never logs.
  - `getBook() -> Book | null | undefined`: undefined while loading or never started.
  - `lineMoves(lineIndex: number) -> string[]`: the loaded line's move strings, for the view.

- [ ] **Step 1: Write failing tests.** Use a small fixture and `buildBook(real JSON)` loaded
  with `fs`.
  - A transposition gives the same name: `1.d4 Nf6 2.c4 e6` and `1.c4 e6 2.d4 Nf6` →
    `openingAt(...).name` is equal and non-null.
  - `1.e4 e5 2.Nf3 Nc6 3.Bb5` → name starts with `"Ruy Lopez"`.
  - Walk-back: the fixture is `["X00","A","e2e4"]` and `["X00","B","e2e4 e7e5 g1f3 b8c6"]`.
    For the history `e4 e5 Nf3 Nc6 Bc4`:
    - index 3 (after Nf3) → name `A`, `inBook: true`;
    - index 5 → name `B`, `inBook: false`, `lastBookIndex === 4`.
  - A custom FEN (`8/8/8/4k3/8/8/8/4K3 w - - 0 1`) → `openingAt` null, and
    `isBookPosition` false.
  - En passant (Review Focus 2): `positionKey` of the history FEN after 1.e4 equals the key of
    `rnbqkbnr/pppppppp/8/8/4P3/8/PPPP1PPP/RNBQKBNR b KQkq - 0 1`.
  - Continuations: from the start position on the fixture, ordered by `lineCount`, and every
    row has a non-empty `name`.
  - `isBookPosition(START)` is true.
  - Every real line builds without throwing, and `book.size > 3000`.
  - `loadBook("file:///nonexistent")` resolves to null, with `console.error` / `console.warn`
    spies never called.

- [ ] **Step 3: Implement.** `buildBook` replays each line from `START` with
  `moveFromString` + `doMove` + `generateFEN`, calling `positionKey` on each FEN and creating
